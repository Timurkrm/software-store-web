# Руководство администратора

## Вход и доступ

**Цель:** открыть административные функции.  
**Действия:** войдите учётной записью с ролью `ADMIN` и перейдите на `/admin`. Для demo-профиля административная учётная запись создаётся только при задании `APP_SEED_ADMIN_EMAIL` и `APP_SEED_ADMIN_PASSWORD`.  
**Результат:** доступна административная страница. Сервер дополнительно защищает `/api/v1/admin/**` ролью `ROLE_ADMIN`; интерфейсная проверка роли не заменяет эту защиту.

## Категории

**Создание:** в разделе категорий заполните название и, при необходимости, описание, затем сохраните. Название обязательно и уникально без учёта регистра.

**Изменение:** нажмите «Изменить», исправьте поля и сохраните.  

**Удаление:** нажмите «Удалить». Удаление отклоняется, если категория используется хотя бы одним продуктом; сначала нужно переназначить или архивировать связанные товары.

## Продукты

**Создание:** в разделе товаров заполните название, разработчика, описание, цену, версию и категорию; ссылка на изображение необязательна.  

**Изменение:** выберите «Изменить», скорректируйте поля и сохраните.  

**Архивирование:** нажмите «Архивировать». Продукт не удаляется физически: он получает статус `ARCHIVED` и перестаёт показываться в публичном каталоге. История заказов и лицензии сохраняются.

## Заказы

**Просмотр:** раздел заказов показывает административный список заказов и их статусы.  

**Допустимое изменение статуса:** UI предлагает отмену только для `CREATED` и `PENDING_PAYMENT`. Сервер проверяет переходы независимо от UI: из `CREATED` допустимы `PENDING_PAYMENT` или `CANCELLED`; из `PENDING_PAYMENT` — только `CANCELLED`.

Статусы `PAID` и `COMPLETED` нельзя вручную выставить через административный API: они достигаются только платёжным процессом. Из `PAID`, `COMPLETED`, `CANCELLED` и `FAILED` последующие переходы отклоняются.

## Ограничения безопасности

- токен JWT передаётся как `Authorization: Bearer <token>`;
- отсутствие аутентификации возвращает JSON `401`, недостаточная роль — JSON `403`;
- пароли хранятся как BCrypt-хеши, не как открытый текст;
- клиентское отображение admin-раздела не даёт привилегий без серверной роли `ADMIN`.
