# Техническое задание

## 1. Наименование

Веб-приложение по продаже программного обеспечения «SoftStore».

## 2. Основание для разработки

Учебный курсовой проект по траектории Web-разработка.

## 3. Назначение

Система предназначена для публикации каталога программного обеспечения, регистрации покупателей, ведения серверной корзины, оформления и demo-оплаты заказов с выдачей лицензий, а также для административного управления каталогом и просмотра заказов.

## 4. Требования к системе

Java 17, Spring Boot, Spring MVC и Thymeleaf; PostgreSQL с Flyway; Spring Data JPA/Hibernate; Spring Security, JWT и BCrypt; Maven; Docker Compose; OpenAPI/Swagger. Архитектура: Presentation → Control → Mediator → Entity → Foundation.

## 5. Функциональные требования

- публичный просмотр и поиск активных продуктов, просмотр категорий и карточки продукта;
- регистрация и вход по e-mail и паролю;
- корзина текущего пользователя: просмотр, добавление, изменение количества, удаление и очистка;
- создание заказа из корзины, просмотр собственных заказов и demo-оплата заказа в `PENDING_PAYMENT`;
- генерация лицензий при успешной оплате;
- роли `USER` и `ADMIN`;
- административные CRUD-операции для продуктов и категорий, архивирование продукта, просмотр и допустимая отмена заказов;
- REST API с префиксом `/api/v1` и Swagger UI.

## 6. Требования к безопасности

Публичны только HTML-страницы каталога, статические ресурсы, auth API и GET-запросы каталога/категорий. Корзина, заказы и лицензии требуют JWT. Admin API требует `ROLE_ADMIN`. Пароли хешируются BCrypt; 401 и 403 возвращаются как JSON `ApiError`. JPA-параметры и Spring Data репозитории исключают конкатенацию пользовательского ввода в SQL; UI выводит API-данные через `textContent`.

## 7. Требования к БД

Используется PostgreSQL. Схема создаётся миграциями Flyway; Hibernate работает в режиме `ddl-auto=validate`. Сущности включают User, Category, SoftwareProduct, Cart, CartItem, Order, OrderItem, Payment и License. Предусмотрены UUID-ключи, внешние ключи, UNIQUE, NOT NULL, CHECK и индексы; заказ хранит snapshot цены позиции.

## 8. Требования к интерфейсу

Thymeleaf-страницы: главная, аутентификация, каталог, карточка продукта, корзина, профиль, заказы, лицензии и admin. Взаимодействие с REST API выполняется через Fetch API; вёрстка адаптируется к мобильным экранам.

## 9. Требования к тестированию

Используются JUnit 5, Mockito и MockMvc. На момент фиксации документации: 42 теста, 0 failures, 0 errors; JaCoCo line coverage — 62.69%; Checkstyle — 0 нарушений.

## 10. Требования к развёртыванию

Приложение собирается в executable WAR и совместимо с external Tomcat 10+. Docker Compose поднимает application и PostgreSQL с healthcheck. Настройки подключения, JWT и demo-admin передаются через environment variables.

## 11. Критерии приёмки

Сборка `mvn clean package` формирует `target/software-store.war`; `mvn clean test` завершается успешно; `mvn checkstyle:check` не выявляет нарушений. В Docker доступны `/`, `/catalog`, `/api/v1/products` и Swagger UI; без JWT `/api/v1/cart` возвращает 401. Авторизованный сценарий cart → order → payment → license проходит успешно.
